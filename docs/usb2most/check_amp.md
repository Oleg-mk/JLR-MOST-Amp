# Звірка емуляції підсилювача з usb2most

Кожна функція `fw/main/amp.c` проти обробника й відправника в `main-v24.bin`. Звірка від 4 листопада 2026, прошивка до неї
74fb1cb.

**Чому usb2most — еталон.** Він працює в машинах як ці підсилювачі. Для XF це той самий підсилювач: каталог SDD дає XF
6H52-18C808-CE і -DE, тобто родину Freelander 2. Журналу кільця з машини в нас немає, тож усе тут із коду usb2most, а не зі
спостереження.

**Як читати.** Розбір кожного обробника: [decode_prefacelift.md](decode_prefacelift.md), [decode_aud3.md](decode_aud3.md). Їх
зробили окремо один від одного, за самим бінарником, не бачачи нашого коду. Найважливіші рядки (SpeakerLevel, Connect, E05h,
E0x Get, ShutDown, запити до майстра, вибір 22.02 і 22.05) я перевірив у дизасемблері сам. Решта спирається на ці розбори,
а спільне для обох драйверів вони прочитали однаково.

Статус рядка:
- **виправлено** — було неправильно, тепер як в usb2most;
- **додано** — у нас цього не було;
- **збігається**;
- **свідомо інакше** — причина в рядку;
- **висновок** — прямого доказу немає, перевірити на першій платі в кільці (кінець файлу).

## Дорестайл: 22.02 і 22.05

| Функція | usb2most | Було | Статус |
|---|---|---|---|
| 46Dh Set | `[рядок, 0, дБ…]`: байт 0 рядок 1..4, байт 1 динамік (0x08034140), шле так само (0x080330E8). 5 рівнів fl c fr rl rr. `[0, 0, 4 x 5]` усі рядки. Без відповіді | **байти навпаки**: `[1, 0, …]` писалось в усі приймачі, `[2, 0, …]` у всі приймачі зі зсувом. Музика могла стрибнути на рівень телефона | **виправлено** |
| 46Dh, рівень понад 0 дБ | не перевіряє; центр буває вище 0 на повній гучності (0x08033604) | Error 06, команда пропадала | **виправлено**: приймається, на виході не вище 0 дБ |
| 46Dh Get | `[r, 0]` → `[00 00, рядок]`, `[0, 0]` → `[00 00, усі]`, інше порожній Status, довжина не 2 → Error `06`. До Set усе −99 дБ | інакше, до Set Error | **виправлено** |
| 466h Set | рядки 1..4, довжина 7, інше ігнорує, без відповіді | Error на все інше | **виправлено** |
| 113h Mute | у списку є, обробника немає | за GeneralFBlock | **свідомо інакше**: каталог; ГУ, що шле Mute, почує його |
| 111h Connect | Result на будь-який приймач; канали не перевіряє; сам шле підсилювачу `c+1 c c+5 c+4` | невідомий приймач і неспадний список → Error 06 | **виправлено** |
| 112h DisConnect | Result на будь-який приймач, маршрут лишає | маршрут знімає | **виправлено** щодо Result; маршрут **свідомо інакше**: приймач має замовкнути |
| 202h, 203h Set | один байт, без відповіді | те саме | **збігається** |
| 427h, 430h, 431h, 441h Set | без відповіді | те саме, зберігається за `[рядок, параметр]` | **збігається** |
| 461h Set | без відповіді | те саме | **збігається** |
| 461h Get | відповідає зі своєї таблиці 45 рядків | лише те, що прийшло тим самим Pos | **свідомо інакше**: ця таблиця для його застосунку; звук від неї не залежить. Побачимо в журналі, чи ГУ питає |
| E04h, E05h, E07h | Set лише повної довжини, Get `[0, 0]` віддає таблицю зі стартовими значеннями | зберігалось будь-що, Get до Set → Error | **виправлено** |
| E08h | Set `[0, 0, 14]` або `[1|2, 0, 7]`, інше Error `06`; Get без Pos, перші 2 байти нулі | як E04h | **виправлено** |
| E09h на основному FBlock | приймає, у списку немає | Error 03 | **виправлено** |
| 001h Notification | нічого не зберігає й не відповідає | таблиця підписок, Status, Error 41h і 20h | **свідомо інакше** щодо таблиці й Status: специфікація, зайвого не шле, бо підписуються на інше. Error **прибрано**: ГУ на старті підписується на функції, яких немає в списку |
| 002h NotificationCheck | немає | за каталогом | **свідомо інакше**: нешкідливо |
| 101h, 102h | приймає, у списку немає, результату в режимі підсилювача не дає | Error 03 | **свідомо інакше**: у списку немає, ГУ не викличе |
| Невідома функція, FBlock | мовчить | Error 03, 01 | **свідомо інакше**: специфікація; запитів таких не знаємо |
| Чужа InstID у 22 | мовчить | Error 02 | **виправлено**: його старт шле 22.20 на AUD3 |

## Перевірити на першій платі в кільці

Цього не закриває жоден код:

1. Чи шле стара ГУ Mute 113h і чи читає EQ через 461h Get. Журнал покаже.
2. Чи рядок 3 на AUD3 навігація, а не щось інше.
3. Крок Bass, Treble і Balance у децибелах.
4. Чи справжній AUD3-8 і -12 теж питає F5.305 на старті.
5. Що означають поля E04h, E05h, E07h, E08h. Вони зберігаються й повертаються, на звук не діють.
6. Чи варто застосовувати 466h для 22.20 до музики. Зараз глушіння музики 20 мс, доки ГУ не задасть рядок 1.

## Що перевіряє це тепер

- `fw/tools/host/golden.py` читає байти прямо з `main-v24.bin` у `fw/main/u2m_golden.h`, а `run.py` щоразу звіряє заголовок із
  бінарником. Самоперевірка порівнює відповіді з цими масивами, а не з набраними мною вручну.
- Самоперевірка проганяє весь старт ГУ з методу +40 його драйвера: Premium, Hi-Line, AUD3.
- `fw/tools/host/mutate.py` повертає старі дефекти по одному в копію `amp.c` і показує, що тести їх ловлять.
